# Editing DNA for each video

Do this by default for every new source, including link-only jobs. A revision keeps the current concept unless the requested change benefits from a new direction. Keep the account's identity and agreed constraints stable while developing a visual interpretation for the specific story.

## Design from the material

Watch/probe the footage and read its source-bound narration before choosing a look. Identify what the viewer should understand or feel, where the story turns and what the footage itself gives you. Save a private `video-dna.md` in the working project, tied to the source hash and version. Keep it short:

- **Concept:** one sentence naming the story, intended reaction and visual idea. Name the source moments that support that choice.
- **Typography:** when straight or italic type makes sense, hierarchy and line grouping, placement relative to face/hands, subtitle and accent colors with sufficient contrast. Choose entrances (soft phrase, stagger, clean reveal, selected token, or behind-person treatment) by meaning and speech. The phrase renderer accepts optional block `fontStyle: "normal" | "italic"`; use this with authored block geometry, size, effects and the profile palette. If using a custom composition, register actual fonts and audit widths again.
- **Animation:** choose motifs, direction, pace, material and transitions that express actions or relationships in this story. Author the hook and hero beats from the content. A cut, clean hold or framing change can be the right beat between richer sequences.
- **Imagery:** decide which clauses need original art, sourced footage, AI illustration or no insert. Record the subjects, actions, visual references and intended placement. Keep related images coherent across the edit.

Treat the DNA as authoring input. Apply those choices to profile and caption blocks, hook, scene composition and generated assets. A written concept with unchanged sample scenes does not count. Use existing technical primitives where they fit and author a composition or asset when those primitives cannot express the intended idea. Preserving an approved brand color or readable font is fine. Avoid repeating a whole combination of typography, positions, effects, transitions, illustrations and hook layout across different videos.

## Optional reference research and generation

When useful and available, search the web for public visual references using general scene terms. Study composition, light, materials and action; save useful references with links. Generate original images matching this edit's concept using available authorized tools. Use a found asset directly only if its rights cover the requested use. Keep private footage, names or unreleased material out of search queries unless explicitly authorized.

Google Flow is optional. Use the requester's authorized Flow session if available and permitted to generate a character, original image or B-roll for the chosen beat. Verify available access and credits before submitting; upload only reference material the requester authorized. Reuse a consistent approved character reference across its scenes, specify action and framing, and review the returned asset for identity, motion, artifacts, and fit before using it. Record the provider, source/permission, file and version. Use original footage, local motion or another permitted tool if Flow or asset generation is unavailable. [Google Flow image guide](https://support.google.com/flow/answer/16729550), [video and reference guide](https://support.google.com/flow/answer/16353334).

## Check before delivery

Review the actual opening, normal subtitle passages and several distinct hero moments. Compare with available recent same-account edits; if it reads like the same template with new words or color, revise the composition, motion or imagery. For the first video, compare with packaged examples and remove borrowed layouts or example scenes that do not fit. Keep the approved craft: real speech clock, intact phrases, clear typography, selected word motion and readable behind-person layers. Judge motion and sound on the rendered MP4. Record only the review actually done. User-selected music or no music remains the rule.
